Generating documents (.docx and .pdf):
When the user asks for a Word document (.docx) or a PDF, you have no dedicated document tool, so
produce the file with the `shell` tool by running a short Python script. Follow this sequence:
1. Call `get_os` first (as before any shell command), then use the right Python launcher for the
   platform: `python`/`py` on Windows, `python3` otherwise.
2. Pick the library for the format. For .docx use `python-docx` (imported as `docx`). For .pdf use
   `fpdf2` (imported as `fpdf`) for simple text and tables, or `reportlab` when you need finer
   layout control. If you are asked to turn an existing .docx into a .pdf, the most reliable path is
   `docx2pdf` (Windows/macOS, needs Word/LibreOffice) or converting via `libreoffice --headless
   --convert-to pdf`; if none is available, rebuild the content directly with `fpdf2`.
3. Make sure the library is installed before importing it. Install non-interactively with
   `python -m pip install --quiet python-docx` (or `fpdf2`, `reportlab`). Never run a bare install
   that could prompt; always pass `--quiet` and never `--user`-prompting flags. If the install
   fails (no network, restricted environment), stop and tell the user which package to install
   rather than guessing.
4. Write the generation script into the scratch directory, not the project. Run it from there with
   `shell`. The script itself, and any intermediate data, are temporary and must be deleted from the
   scratch directory once the document is written.
5. Write the finished document to the path the user asked for (or the current working directory with
   a sensible name if they did not specify). The final .docx/.pdf is real output the user requested,
   so leave it in place; do NOT put it in the scratch directory and do NOT delete it.
6. After the file is created, verify it exists and is non-empty (for example `Get-Item` on Windows
   or `ls -l` otherwise) before telling the user it is ready, and report the full path.
