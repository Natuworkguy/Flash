Point the user to the right place, briefly:
- Models: /model to pick, /fallbacks to set models to try when one fails, /compare a vs b: question for a blind test, /host to switch Ollama server. Sparks use their own fallbacks first, then the chosen model's global fallbacks; their model picker shows that global chain. A long-running process rechecks installed provider extensions before reporting one missing.
- Watch Settings: turn off Update computer addresses to stop accepting automatic local IP/address updates from Flash and keep the saved address list. Existing saved addresses can still be tried when a connection fails.
- How Flash works: /auto on|off|ultra (ask first, autonomous, or UltraAuto), /think auto on|off, /instructions for custom instructions, /systemone for a model that reviews autonomous commands.
- Memory and learning: /memory, /forget N, /skills, /good and /bad on the last reply.
- Conversations: /resume, /fork, /forks, /compact, /context, /clear, /undo (take back the last turn's file changes), /btw (a side question while it works).
- Apps: /mcp (connectors), /extension, /email, /calendar, /computer, /voice, /secret (keys Flash uses by name).
- Ongoing work: /sparks, /agents, /plan, /notify.
- Web page: /web (lan for a phone on the same network, tunnel for anywhere, port N).
- Network address: the address shown and put in the QR is the Wi-Fi or Ethernet interface with the default route, never a VPN (utun), VM bridge or Internet Sharing address, even when a VPN takes over routing. The list the watch syncs holds every address: that one first, then the Mac's other IPv4 addresses (VPN and bridge included), then its .local name, plus the public link while it is on. The watch tries each in turn (a quick 3-second check apiece), uses the one that answered first next time, and keeps the whole list rather than dropping one that failed once. When pairing by hand, several addresses can be typed, split by commas. If the watch only knows an old address, pair it again with the address Flash shows now.
- Health: /doctor (and /doctor fix), /version, /update, /stats.
- Settings are saved in ~/.flash.env with /set NAME VALUE; the web page has Settings for most of them.
- Dashes and emojis: Settings has "Remove em dashes" (on by default, REMOVE_EM_DASHES) and "Remove emojis" (off by default, REMOVE_EMOJIS). On, Flash strips them from everything it writes, replies and every tool call alike; code is kept as written.
- Calls: Settings, under Calls, has "Call greeting" (CALL_GREETING_MODE): the standard greeting (default, "Hi, this is an automated assistant calling on behalf of" the user's first name), the user's own (CALL_GREETING, where {name} is their first name), or "Let Flash write its own".
- Extension panels that talk: a panel page can reach Flash's model through a "run" button with "where": ["terminal"] (hidden on the web page), called from the page as parent.Flash.request("ext-button", id, {extension, text}); the program can import flash (it is on PYTHONPATH) and print the reply. Stickbuddy (~/Desktop/Projects/flash-stickbuddy, install with /extension install path@that folder) does this: a stickman panel you hover, poke, tickle and drag, with lines from the model and canned ones when it is slow.
- Ethics evaluation: the ethics-eval extension, its own project at ~/Desktop/Projects/flash-ethics (install with /extension install path@~/Desktop/Projects/flash-ethics), puts a model in simulated dilemmas (lying to a customer, skipping a safety test, defaming a tenant, reading medical records, power-seeking, unsafe orders, biased hiring, hiding a mistake, manipulating an elderly user) with fake tools that only record what it tried; a judge model scores each transcript 0-10 on honesty, harm avoidance, fairness, autonomy, refusing unethical orders, helpfulness and restraint, and a report with per-scenario results and an overall score out of 100 goes to ~/.flash/ethics-eval/. Its "Ethics eval" sidebar panel picks the scenarios, the model under test, the judge and turns, runs the evaluation in the background with no time limit and shows it live (the scenario, each turn, the model's thinking and replies, every simulated tool call with its fake result, the judge's rubric scores as they come in, elapsed time and progress), and opens past reports (overall score, a table per scenario, scores by criterion and each transcript). It also runs with /ethics (list, or scenario ids; stops starting scenarios after about 9 minutes) or the run_ethics_eval tool; its settings set the defaults; add scenarios to its scenarios.json.
- Intelligence test: the intel-eval extension, its own project at ~/Desktop/Projects/flash-intel (install with /extension install path@~/Desktop/Projects/flash-intel), asks a model questions in math, logic puzzles, reading comprehension, coding, common sense, patterns and sequences, and instruction following, grades them (automatically wherever it can: numbers, exact words, letters, required words, checks on the reply's form, and the model's Python run against tests in an isolated, time-limited Python that refuses code touching files, processes or the network; a judge model grades only open answers) and saves a report (Markdown and JSON) in ~/.flash/intel-eval/. Its Intelligence test panel in the sidebar picks the model, the judge and the categories, runs the test in the background and shows it live (each question, the model's thinking and answer typed out, a right or wrong reveal with the expected answer, a bar per category, the running score and elapsed time), and opens past reports. It also runs with /intel (list, or categories or question ids; stops after about 9 minutes) or the run_intel_eval tool; its settings set the model and judge; add questions to its questions.json. /intel hard runs its hard tier for frontier models: about 33 questions in seven hard-* categories, regenerated with new numbers each run (seed saved in the report) and graded strictly (exact answers, one number only, every part of a multi-part question right, no partial credit).
- Printing: on a Mac, Flash can list printers and print a file or a made document (list_printers, print), asking the user yes or no every time (see print-a-file).
- Apple apps on a Mac: Apple Calendar is a calendar choice beside Google and iCal feeds (Settings, Connectors, Calendar; see manage-the-calendar), the reminders tool lists, adds and ticks off Apple Reminders (see use-reminders), and send_imessage can send a file while read_imessages names attachments (see send-messages). Adding or changing anything asks the user first.
- Location: with "Let Flash see my location" on in the Apple Watch app's Settings (off by default), the watch tells Flash where the user is and the user_location tool gives it (see know-where-the-user-is). Off, nothing is collected or sent.
- Reminders at a time: remind_me has Flash itself notify the user then, kept across restarts (see remind-the-user-later). Apple Reminders are separate.
- Permission mode on the watch: the Apple Watch app's Settings has a Permissions section to pick Ask first, Auto, or UltraAuto (listed only once UltraAuto is allowed in Flash's Settings). It sets the same mode as the mode button by the message box.
- @mentions on the watch: in a chat or a team chat on the Apple Watch app, the @ button by the message box lists the sparks; the one picked is shown above the box and its @handle goes in front of the next message. Dictating "at Engineer" (at the start, or after a comma or full stop) or "@Engineer" anywhere becomes @engineer-spark before sending, so Flash routes it to that spark as it does a typed @mention in the page.
- Keep awake: Settings has "Keep this Mac awake while Flash runs" (on by default). While Flash's server runs it holds macOS idle sleep off (caffeinate), so the watch can still reach Flash and sparks can still call when the user is away. The display still sleeps, and closing the lid on battery still sleeps the Mac; macOS lets no app stop that. If the computer cannot be reached, the watch says "Can't reach your computer right now." instead of an error.
- Devices: devices tells the Mac's battery, network, connected Bluetooth devices with their batteries, and the Apple Watch's battery as it last sent it (see check-devices-and-batteries).

If something is broken, suggest /doctor first.
